# The chart tracer draws an expanded Column Graph

Charts are M1's hero slice (REQUIREMENTS §9.0), and no chart code existed. M1 (§9.1) lists nine `chart_create_*` tools, one for each of Illustrator's graph tools (decision 3, §6.4.5), plus `chart_update` and `chart_expand`. The first benchmark task in §1.5 is a column chart. This ADR records the tracer, `kalamo_chart_create_column` (#260): what it takes, how it lays a chart out, which colours it uses, why it draws plain Nodes, and what the nine tools would cost in ADR-0088's tool-definition budget.

## Decision

1. **Input.** `kalamo_chart_create_column {docId, parentId, data, encoding, frame: {x, y, width, height}, intent?, txId?, ifRev?}`, with strict keys (ADR-0050). Core's `ChartInput` holds every field but the write options, so the other chart types can take the same schema.
   - `data` is `{rows: [{field: string | number | null}]}` or `{csv}`, at least 1 row and at most `maxChartRows(S)` for S series (987 for 1, 491 for 3, 35 for 50; see Consequences),, RFC 4180 text whose first record names the fields. Quoted fields may hold commas, doubled quotes and line breaks, and CRLF or LF ends a record. A record with a different number of fields from the header is `INVALID_INPUT` at `data.csv`, and so is a quoted field that never closes.
   - `encoding` is `{x, y}`: `x` names the category field, and `y` names one value field or a list of them, 1 to 50, one series each. A field that no row has is `INVALID_INPUT` at `encoding.x`, `encoding.y` or `encoding.y[i]`. A field named twice, or `x` named as a series, is `INVALID_INPUT` at `encoding.y`.
   - Numbers parse as F-CHART-02 says. Leading and trailing white space, one currency sign (`\p{Sc}`) after an optional sign or at the end, a trailing `%`, and commas between a digit and a group of three digits are ignored, so `1,234`, `12%`, `$5`, `5 €` and `-$1,234.5` parse. `%` does not divide by 100: `12%` draws as 12, the value as written. An empty or white-space cell, or `null`, is a gap: its column is not drawn, and its place in the cluster stays empty. A 0 draws no column either, rather than a rect with no area that `kalamo_validate` would report as `zero_area`. A CSV's leading byte-order mark, which Excel writes, is dropped. Any other value, including one too large to be finite such as `1e999`, is `INVALID_INPUT`. A field is read only from a row's own keys, so a field named `constructor` is never Object's. In rows its `path` is the cell, such as `data.rows[3].sales`. In CSV every cell's path is `data.csv`, and the message names the row, counted from 0 after the header, and the field. A row without a category is `INVALID_INPUT` the same way.
2. **Output.** One Group named `Column Graph`, the Illustrator name of the graph type, on top of `parentId`, in one `createNodes` and so one Transaction and one undo step. Its children, bottom to top:
   - `Value Axis`: the axis line, a tick mark and a right-aligned label at each tick. Ticks are d3's `ticks` with a target of 5: the step is 1, 2 or 5 × 10ⁿ, from the error ratio of a fifth of the range against √50, √10 and √2. The range runs from the lower of 0 and the least value to the higher of 0 and the greatest, so negative values draw below the zero baseline. When every value is 0, the range is 0 to 1. So 0–7 ticks by 1, 0–1234 by 200 up to 1400, and −40–60 by 20.
   - `Category Axis`: the baseline at 0, across the plot, and a centred label under each category, below the plot.
   - One Group per series, named after its field, holding a `rect` per category whose value is not a gap or 0, named after the category. Columns have one Fill and no Stroke.
   - With two or more series, `Legend`: a swatch `rect` and a name for each series, in a column at the frame's top right. Illustrator's default Legend sits to the right of the graph, from its top.
   The tool returns the receipt plus `outline`, core's `outline` from the Group at depth 2: the parts and what each holds. This is like `path_edit`'s receipt, which adds `d`.
3. **Layout.** Everything lies inside `frame`, Strokes included, which a core test checks with `visibleBounds`. The constants:
   - Each category has an equal slot along the plot. Its cluster takes Illustrator's default Cluster Width of 80% of the slot, centred. Each series takes an equal share of the cluster, and its column takes Illustrator's default Column Width of 90% of that share, centred. These are the Graph Type dialog's defaults: Cluster Width "at 80%, the width of each grouping of three columns takes up 80% of the available space between tick marks", and Column Width is "how much of the space available is used for each column within a cluster" ([CreativePro, *No More Boring Graphs EVER*](https://creativepro.com/illustrator-how-to-no-more-boring-graphs-ever/)). That wording settles which percentage is which; the issue's "90% cluster and 80% column" had them the other way round. Adobe's help pages refused automated reads, so the 90% Column Width is the dialog's default as Illustrator shows it, not confirmed from an Adobe source here.
   - Text is Point Type in the bundled font, Source Sans 3. The size is a thirtieth of the frame's shorter side, rounded to 0.1 pt and kept between 6 and 12 pt: 10 pt in a 400 × 300 frame. The other spacing follows from the size: ticks of half the size, a quarter of the size between a tick and its label, half the size between the plot and the category labels, Legend rows 1.5 times the size apart with square swatches the size of the text, and a gap of the text size between the plot and the Legend. Axis lines and ticks are 1 pt black Strokes. The plot leaves half a label's height above the top tick, so its label stays inside the frame, and half a Stroke at its right end when there is no Legend.
   - A frame too small to leave the plot any width or height beside the labels and Legend, or too short for the Legend's rows, is `INVALID_INPUT` at `frame`.
4. **Labels that do not fit.** When the widest category label is wider than a category's slot, the labels overlap their neighbours, or the outer ones leave the frame. The chart is still drawn, and the receipt's `warnings` carries one `CHART_LABELS_OVERLAP` on the Group, giving the label's width and the slot's. It is a new code, not `TEXT_OVERFLOW`. That code means an Area Type does not show all its text, which `kalamo_validate`'s `text_overflow` rule checks. Here every label is Point Type, drawn whole, and only overlaps.
5. **Palette.** Okabe and Ito's colour-blind-safe categorical palette, without its black, which the axes use. It is reordered so that the first four colours have at least 3:1 contrast with white, WCAG's minimum for graphics: `#0072B2` (5.19:1), `#D55E00` (3.87), `#009E73` (3.42), `#CC79A7` (3.06), then `#E69F00` (2.25), `#56B4E9` (2.31) and `#F0E442` (1.32). An eighth series starts again from the first colour. Okabe and Ito chose the eight colours to stay apart under each common colour-vision deficiency. Themes, and the palettes F-CHART-04 asks for beyond this default, are later work.
6. **Expanded output.** The tracer draws what F-CHART-06's Expand Chart will leave: plain Groups, rects, lines and texts, with no `chart` node type and no data binding. An Agent or a person can select and edit any bar or label at once, and every existing tool already reads, renders, exports and validates the result. The `chart` Live Object (F-CHART-05), `chart_update` and `chart_expand` come in the next ticket. That ticket wraps the same layout function, `columnChart`, so the node it keeps will generate these children.
7. **Nine tools and the budget.** The column tool's definition, measured as the budget test measures it, is 3,240 bytes: 990 of description and the rest the name and input schema. It brought the total from 106,576 bytes, on main after #258 and #259, to 109,816 of 112,000, so the budget is unchanged. MCP gives each tool its own input schema, so nine named tools with this schema would each repeat it. Nine tools of this size come to 29,160 bytes, and the total to 135,736: 23,736 over the budget. Even with each other type's description cut to one sentence, about 200 bytes, the other eight would add about 19,600 and the total would be about 129,400. One `kalamo_chart_create` with a `chartType` enum would cost about this tool's bytes plus 150 for the enum and about 200 for each type's own sentence, around 5,000 in all, for a total near 111,600. So nine named tools do not fit, and decision 3's own fallback in §8.2, one tool and an enum if the number of tools becomes a problem, does. When the second chart type lands, chart creation becomes one `kalamo_chart_create {chartType, …}` taking this `ChartInput`, the way Illustrator's Graph Type dialog switches one graph between types, and `kalamo_chart_create_column` is renamed to it. No external client depends on the name before the M1 announcement, as ADR-0069 found for its renames. `chart_update`, `chart_expand` and `diagram_create` will then need the budget raised by their measured bytes, as ADR-0088's rule 4 allows.

## Considered Options

- **The `chart` node now.** Rejected for the tracer: it needs a node type, a stored data binding, regeneration and Expand at once. The expanded Group is useful on its own, and the next ticket keeps its layout.
- **`TEXT_OVERFLOW` for labels that do not fit.** Rejected above: it would claim text is hidden when it is drawn, and `kalamo_validate` would not report it.
- **Hiding labels that do not fit**, as REQUIREMENTS §6.4.5's "labels hidden" warning suggests. Rejected for now: F-CHART-10's label avoidance is P1, and a hidden label is harder for an Agent to notice than an overlap the warning names.
- **Raise the budget for nine named tools.** Rejected: about 23.7 KB more on every turn of every Agent, against ADR-0088's measured cost per turn, when one tool and an enum fits within it.

## Consequences

- REQUIREMENTS F-CHART-01 and §6.4.5 say that only `column` exists so far and that it is expanded output, and point to this ADR for the merge. skill://kalamo/drawing-conventions has a Charts section.
- `fixtures/agent-benchmarks/chart.md` is the first chart benchmark task: quarterly sales for three regions, checked for one `Column Graph`, a Group per region with a rect per quarter, and heights proportional to the values within 1%.
- A chart is one `createNodes`, so it counts toward its 2000 Nodes. For R rows and S series it is at most 25 + R + S + R·S Nodes, plus 1 + 2S for a Legend with 2 or more series: the Group, the Value Axis, its line and at most 10 ticks of a line and a label each (`niceTicks` spans less than 7.91 steps, plus one step at each end), the Category Axis and its baseline, a label per row, a Group per series and a rect per value. `maxChartRows(S)` is the largest R that fits whatever the values: ⌊(1975 − S − (S > 1 ? 1 + 2S : 0)) ÷ (S + 1)⌋, 987 for 1 series, 491 for 3, 35 for 50. `columnChart` checks the row count, not the values, before it lays anything out, so one row more fails `LIMIT_EXCEEDED` at `data` naming that number, through `rows` or `csv`, even when most values are 0 or gaps. The `rows` schema allows at most `maxChartRows(1)`, so more rows than one series fits are the schema's `INVALID_INPUT` at the same number. The code marks the one-write ceiling with a `ponytail:` comment.
- Numbers on the Value Axis are written as JavaScript writes them, with no thousands separators or units. Axis titles, data labels, sorting, number formats and themes are F-CHART-03 and F-CHART-04 work.
